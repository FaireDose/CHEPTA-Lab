# Issues and routes register

One row per problem a process shows, keyed by the problem at the level where it occurs (the maintainer, 2026-11-12;
docs/HANDOVER.md, queue rows B and C):

- **separation**: keyed by the mixture and its behaviour (an azeotrope, two liquids, an associating acid), so that
  different reactions with overlapping products meet in the same row;
- **reaction**: keyed by the reaction's behaviour (equilibrium-limited, strongly exothermic, side products);
- **plant**: whole-flowsheet problems (recycles, purge and make-up, heat integration).

A complete flowsheet is never a key: it stays the case, and links to its rows. "Seen in" counts different papers, not
runs. A route counts as usable only where a paper or a CHEPTA run shows it working; a route named only by an AI, or
only by a paper's literature review without its own results, is a **lead**, marked so. Locators point to the paper
(page, section, table) or to a CHEPTA run in a case folder.

## How to add a row

Add a row only for a problem a case actually shows, with its locators. When a second paper shows the same problem,
add it to "seen in" (count papers, not runs) and add its route; never merge two problems because their names look
alike. Keep CHEPTA's answer as it was in the release named, and update it when a later release changes it.
